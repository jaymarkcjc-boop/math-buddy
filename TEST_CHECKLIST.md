# Acceptance checklist (run on your Mac, Android and iPhone)
Use fictional data only. Record device, browser/OS version, app version, date, expected and actual result. Do not invite real learners until issues are fixed and approval is obtained.

- [ ] Served home screen opens, no console errors, no horizontal overflow at phone widths.
- [ ] Create DEMO01, start fraction addition at level 1, answer incorrectly twice; hint then worked answer appears.
- [ ] Enter equivalent fraction/decimal/mixed-number answers; reject 1/0, invalid text and empty answers.
- [ ] Choose visual; relevant visual appears and unaided score does not count an assisted answer.
- [ ] Complete 3 unaided correct adaptive items for one skill at level 1; next item advances. Complete 2 non-unaided items at current level; next item decreases. Mixed sessions adapt by skill.
- [ ] Finish 5-item practice session, view points and session summary; reload midway and confirm resume.
- [ ] Start independent check: no hint/AI controls, one answer per item, solutions only after all ten items. Results logged as check.
- [ ] Switch English/Filipino/Bisaya; tutoring feedback changes. Have teachers validate translations.
- [ ] Create DEMO02, verify separate local progress; Teacher shows both local profiles.
- [ ] Attach fictional handwritten JPEG/PNG, preview, reload, view in Teacher, download and delete.
- [ ] Export Excel; open in Excel or Numbers. Verify 4 worksheets and matching item/attempt/session totals. Check photos are not included.
- [ ] Install from HTTPS, load online once, reload, turn on airplane mode and reopen: practice, progress and export should work locally. Optional AI should fall back.
- [ ] Reconnect; share published app URL to Messenger manually. Verify configured authorized Page shortcut.
- [ ] If optional AI backend is implemented, test valid/invalid/timeout responses, that no learner identity is sent, and that math answers remain engine-controlled.
- [ ] Test accessibility, data storage eviction, limited connection, safe delete, and recovery. Central backend/authentication must be implemented and independently reviewed before real learner use.
